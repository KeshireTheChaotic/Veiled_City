## Implemented contract and native routes

The existing combined GM request now offers closed v1 `ordinary_effect_proposals` (at most four), with no new provider stage or call. Fields: `version`, `accepted_intent_ref`, `effect_class`, `adapter`, `prerequisite_ref`, `payload_json`. The action reference is either an actual native ID or the exact current source clause resolved uniquely against native accepted occurrences. Ambiguous/foreign/stale sources cannot execute. `payload_json` is itself closed: `{when,query}` for observation or `{when,intent}` for existing delegated adapters. Native `when` is `no_roll`, `success`, or `failure_fear`, not a model success label.

`ordinary-effect-proof` rereads current owner/control, original source/hash/offset, active world ancestry, session/scene/location, withdrawal and non-PvP scope. A real native outcome receipt and actual saved request/dice are mandatory; post-resolution follow-through never reruns the consumed native mechanic. The original versioned native GM ruling's location and context anchor new follow-through; mutable intent metadata cannot relocate a past success. Legacy outcomes lacking that native context remain held rather than retroactively upgraded. The provider receives only bounded owner-scoped locators (latest 20, explicitly labeled 120-character excerpts rather than complete source spans); lookup is not authority and missing locators cannot authorize anything. Mandatory instructions/context are not dropped by prompt compaction. This bounds the new interface, not a claim of measured token optimization or complete historical retrieval.

|---|---|---|
| `observation` | Existing `renderWorldObservation`, native selected facts and occupancy, exact fact/source proof | Only entitled established NPC/location fields; no invented discovery. Result scope can narrow, never widen |
| `delegated` / NPC intention | Existing `dispatchAiIntents` → goal propose/reprioritize/pause/resume | Actual NPC, local legitimate owned knowledge, proxy/personality/goal/delegation checks. Internal motivation remains **GM-only**, never automatic player knowledge or PC reaction |

No PC movement, forced custody or inferred restricted access. This materializes supported facts, not arbitrary new obstacle fiction |
| `delegated` / service consequence | Existing consequence adapter → matched native service handler | Current physical causal source, exact target/delta/location and existing delegated cost/review gates. No free damage, invented physical event or fabricated consequence completion |
| Other classes | Existing scoped unsupported-action review | Generic clocks/exposure, inventory/evidence custody, PC effects, capabilities, death and disclosure have no generic bridge. Their existing dedicated native paths remain available; absent eligible adapters are held, never cosmetically substituted |

Delegated effects share the same per-opportunity budget with existing `ai_intents`. Private-result/private-scene effects retain existing `private_allow` and private-causality restrictions. No source or field labeled `gm:true`, no claimed Critical, no saved high total, and no generic no-roll receipt grants material authority. Actual native success is only a precondition; the adapter separately proves the consequence. Native no-roll adjudication retains empty mutations/dice; a separate eligible effect receives its own `ordinary_effect_receipt`.

## Review, persistence and publication

Unsupported effects use existing GM-private `unsupported_action` storage, with current native ancestry, bounded diagnostic and `needs_review`. They do not overwrite the original action outcome or block siblings. An invalid foreign action receives only a current caller-bound private diagnostic. A pending real roll may later satisfy the same immutable proposal; no roll/spend is chosen automatically.

Native child `ai_intent` records retain `ordinary_effect` binding. Generic GM approval rereads the original causal source and actual prerequisite; retraction or substituted terms cannot bypass the bridge through that older inbox. Bound children need a fresh proposal instead of generic modification. Existing legacy intents without bindings retain their original workflow.

Existing `/vc-roll window json` controls now support:

```text
{"op":"action-review-inbox"}
{"op":"action-review-effect-retry","review":"<id>","revision":"<current revision>"}
{"op":"action-review-effect-withdraw","review":"<id>","revision":"<current revision>"}
```

Retry is authenticated GM revalidation, not an approval override, alternate PC choice, new capability or fabricated source. Only the original current owner withdraws follow-through; the completed action/dice/resources are not withdrawn. Old action-withdraw/replace controls cannot act on effect-only reviews. No live command registration is needed or performed.

The existing common `native_outcome` renderer accepts `ordinary_effect_receipt` read-only. Native effect identity binds proposal and original scope; actual payload, native child, current target, all source prerequisites, actor/control, exact result and audience are revalidated after restart and at final outbox delivery. GM-only targets remain GM-only even when an owner caused the change. Certified character observations go only to that owner; no private result becomes public proof. The original raw candidate paragraph remains quarantined; independent safe output continues. Source retraction holds future delivery without reversing legitimate effects. Uncertain delivery retains the existing no-blind-repost behavior.
