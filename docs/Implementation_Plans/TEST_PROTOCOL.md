# Fresh, changed-code-only test protocol

**For this initiative:** Do not run, import, copy, modify/re-enable, or repurpose legacy tests, historical fixtures, golden output, old suite launchers, or legacy workflows. Do not run `npm run validate`, `validate:extended`, or `npm test` as part of a focused feature change. Migrate the covered production code, establish passing replacement coverage, then remove the obsolete legacy test suite. Preserve production legacy readers when persisted compatibility still requires them; test-suite retirement does not authorize reader removal.

**NO TEST WATCHING OR POLLING:** [TEST_EXECUTION_NO_POLL.md](TEST_EXECUTION_NO_POLL.md) governs the execution lifecycle. Start a batch once, use one blocking call with an adequate timeout or a detached runner while doing independent work, and collect one final result only at a natural milestone. Never repeatedly inspect process/session status or stream live output. A running test is not a passed test.

Create focused Node tests under `bot/tests/ai-gm-2026-10/`, named by feature ID. Tests must import only currently modified production modules plus Node standard libraries and new feature-local fakes. Use temporary disposable SQLite storage, injected deterministic dice/clock, mocked provider and Discord; zero network/prod DB by default. Run `node --check` only on changed JS/MJS and `node --test tests/ai-gm-2026-10/<feature>.test.mjs` from `bot/`. If a changed shared module affects several codepaths, write a focused cross-boundary test scoped to those changed contracts. Record each test run and its actual outcome as complete after its single execution; rerun only if the production code under test changes. Final gate covers production code modified in the initiative without repeating unchanged completed tests.

To adopt CI, create a new opt-in workflow and selector, which must demonstrably exclude inherited validation. Existing repository workflow is historical; changing or disabling it requires explicit review, not a silent weakening of security. Record exact SHA, command, test count, exit code, skipped/failed cases and input/test hashes. A passing delta is not full product qualification, real Discord proof or a release certificate.
