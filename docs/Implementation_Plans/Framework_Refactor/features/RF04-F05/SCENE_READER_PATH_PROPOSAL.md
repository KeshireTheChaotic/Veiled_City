Repointing that array member retains the child-process import and existing exit-status assertion, while changing the particular entrypoint under examination. This is a computed import path, not a literal `import(...)` argument, so the current import-only authorization should not be silently extended to it. No claim is made that the child process passes after repointing.

Deleting that reader would break this test's stated compatibility contract. The current legacy-script permission does not authorize changing or removing this fresh test. `rf04-f04-c01.test.mjs` already maps its historical source inspection to `frameworks/session/scene-setup-service.js`; it is a separate evidence record, not a reason to assume the compatibility test can be retired.
