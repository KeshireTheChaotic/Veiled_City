# RF05-F04 C130 — Native action-plan source boundary

Move the three Native application consumers (`pvp-damage.js`, `pvp-terminal.js`, and `typed-roll-outcomes.js`) from the Intent root compatibility shim to a fixed Native-owned two-function consumer (`buildActionPlan`, `transitionAction`) supplied by the existing Daggerheart–Intent pair. Keep the original Intent implementation, root compatibility facade, transaction call sites, inputs, return values, errors, receipts, and startup behavior unchanged. Bind the pair during existing application startup before these lazy Native services are first used. Qualify actual SQLite plan persistence/replay, the terminal transition interface with a synthetic receipt reference, and fail-closed composition. This does not authenticate Native receipt provenance or qualify an effect; existing Native callers retain that responsibility. No Daggerheart rules or Intent scheduling policy move.
