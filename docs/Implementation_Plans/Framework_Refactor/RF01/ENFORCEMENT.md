# Executable boundary policy

From repository root, run `npm --prefix bot run architecture:check`. This parses active `bot/src`, offline architecture tooling and the two supported export/cost CLI sources without evaluating them. It does not discover or execute old suites, fixtures or services. Acorn 8.15.0 is a pinned development dependency; runtime startup does not import it.

The gate combines exclusive path ownership, actual ESM import/re-export/literal-dynamic edges, exact public entrypoints, alphabetical two-framework adapters, registered consumers, external capability ownership and individual cyclic import edges. Unknown ownership, unsupported source extensions, computed imports, module-loader/eval candidates, parse errors and unregistered implementations fail. Package import aliases resolve to their actual target owner; private or third-framework imports cannot be hidden behind a `public.js` basename.

`architecture:strict` intentionally exits 1 while original coupling remains. The default ratchet permits only the counted occurrences recorded in `TRANSITIONS.json`, constrained by `TRANSITION_BASELINE.json` at intake SHA `0abf4be1d45e87abb2df4416f0e0f546b90cce72`. There is no acceptance/rebaseline CLI. Each record names a source, owner, exact violation/edge, maximum count, removal feature and expiry phase. Added edges within an unchanged strongly connected component still fail. New packages cannot receive old-path exceptions or forward old monoliths.

At migration, remove the resolved transition records in the same change. Unused and expired records fail; do not expand the frozen baseline. A feature deadline names accountable work; the machine enforces its phase expiry. For later phase gates explicitly pass `--phase RF0N` and advance package commands during that phase. RF07 rejects every retained transition. Exceptions are source-edge observations, not blanket permission for any behavior in a 211-module component.

`BRIDGE_CONTRACTS.json` is the current registry; its readable view is the parent `BRIDGE_REGISTRY.md`. Two adapters and a composition consumer exist; they are **CONTRACT_ONLY_UNWIRED**, not integrated replacements for native runners. The remaining 61 records are source-backed proposals. A registered fresh test path proves the reference exists, not that it passed; terminal evidence lives in feature ledgers.

Static enforcement cannot prove that all domain logic inside a correctly labeled module belongs there, nor detect every indirect JavaScript side effect. Known module-scope resource constructors/connect/write calls are review gates, not complete effect analysis or a security sandbox. Dependency injection independently rejects cycles/missing/duplicate bindings before factories run, constructs lazily per instance, and does not import database/provider/Discord clients. Synchronous factory construction may produce asynchronous service methods; no async I/O is performed at composition import. Failed construction is memoized within that container to avoid an automatic repeated resource attempt.

Physical migration, actual runner adoption, single-transaction decomposition and gameplay/replay equivalence remain RF02–RF07 work with fresh affected-code tests. No new narrative constraints, schema migration, production validation or release authorization follows from RF01.
