# Unified Arbitration: live authority gateway migration matrix

UA13 inventory checkpoint: `codex/audience-first-narrative-v9` at `a4ff3759fb8964c1f45ed60600bcab2e656623ea`, application `0.0.0.1`, schema 460. This records current reachable paths, not implemented migrations. UA8–UA12 and UA14–UA15 are still partial. The separately deferred post-UA PvP/Fear plan is not applied here.

Accepted typed intents are canonical adjudication inputs; human declarations own intent; native receipts own outcomes.

## Entrypoints and execution boundaries

The player GM lane is `index.js:processPartyTurn/processPrivateTurn` → `GMService.runTurn` → `commitGmTurn` → `state.js:applyAuthoritativeMutation`. That state boundary persists typed owner sources, stages PvP/action windows, and calls `applyUnifiedArbitration` or the existing `adjudicateGmRuling`/`adjudicateAcceptedIntent` route; only final commit calls `executeUnifiedGmActions`. The writer does not execute mechanics. The same native arbitration origin is bound for the World Director. Separately, `simulation.js:commitNpcDirector` uses `dispatchAiIntents` and the civic simulation executor. A simulation score is not a PC attack/result receipt.

Human command inputs reach `commands.js:executeCommand` only after authenticated Discord user/role handling. `isGM(db,interaction)` is transport-derived, not model JSON. `/vc-roll adjudicate` invokes `adjudicateRollSource` or `reviewTypedRollOutcome`; `/vc-roll effect` passes native GM status only to review/attack operations, while owner approval/Armor uses the actual user. `/vc-roll window` owner reactions and choices do not gain a GM role. The city command router and simulation command adapter retain their own administrator/GM checks; calling an exported native function from model text is not an available capability.

Every migration below needs a distinct sealed native AI-GM source and a verifier at **all** consumers, not merely replacing `human_reviewed` with `native_grounded`. Existing human sources remain readable. New permissions must revalidate source span/hash, owner/principal, session/scene/target, current rule/equipment/feature, audience, costs and request revision before RNG. A migrated ruling never executes a PC die or selects an optional PC cost.

## Reachability and deletion findings

All tabled gate families have current consumers in the player GM, Director/delegation or authenticated command paths. **None is deletion-eligible merely because its message contains “human review.”** `human_reviewed` is consumed by preparation, options, collaboration, `typed-roll-proof`, narrative/evidence reconciliation and neutral-result recovery. Migrating just the producer would create pending requests that fail live/restart readers; migrating only a reader would admit unproved sources. `native_grounded` in the existing ordinary Difficulty path is not a general GM capability or a substitute for attack/feature/participation proof.

Additional current references in `action-continuation`, `director`, `gm`, `index`, `narrative-integrity`, `typed-intents`, `scene-entry`, `simulation-schema` and `supply-dependencies` include review statuses, UI/proposal guidance and downstream read guards. They must be assessed with their particular native adapter rather than removed by text search. Source checks, owner controls, receipts and privacy remain read-side dependencies even with the fresh-database deployment policy. No legacy symbol or plan is deleted in this inventory change.

## Migration gates and present limitations

UA14 needs one native AI-GM adjudication proof accepted at modifier/attack/alternate-trait/participation/effect consumers and their result readers, with exact grounded source mappings. Every migrated family needs a real production-path positive and its forged/wrong-owner/stale/secret near-neighbor negatives. A new model role or `gm:true` field is not a valid test fixture for that permission. Already resolved neutral dice require unchanged contemporaneous grounding or remain reviewed. Existing pending owned dice and original human sources must remain valid.

UA15 must retain configured manual/delegation policy and move only ordinary supported gameplay to the authorized native path. Missing feature, host, power, range, consent, source or disclosure is a specific adapter/authority hold, not a reason to auto-approve. This audit does not claim UA14/15 migration, general remote/cutaway support, all feature execution, whole-plan qualification or deployment. Native consent for current PvP is unchanged. No runtime, DB, flags, provider count or production behavior changes in this matrix-only checkpoint.
