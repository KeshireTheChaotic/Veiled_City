# Scene entry and actor-relative narrative validation — 9.2.0

The diner failures exposed a missing bridge between authenticated entry prose and saved scene occupancy. `I walk into the diner...` was not recognized as an attempt, no arrival was established, and a movement/status claim could require an NPC witness even when its actor was the player or narrator. Disclosure similarly assumed every nonempty actor was an NPC and required an NPC knowledge key identical to the fact ID. Error logging discarded the rejected claim diagnostics.

The parser now recognizes conservative first-person walk/enter/step/go attempts, including a leading Discord mention. The authenticated public/private message paths stage entry review before GM turn generation. OOC, hypothetical and quoted third-party entry text does not authorize movement. A named entry target is parsed conservatively; this is not unrestricted language interpretation.

If the target matches the PC's already-saved established location, a public declaration can reconcile native attendance/presence directly. Otherwise, a character-private `scene_entry` request records exact owner provenance and current session/scene/prior location. It does not create a place, move a PC, infer occupants, grant knowledge, spend resources or advance time. The player receives open clarification rather than a generated claim of success. Existing `natural_language` and `scene_continuity` flags enable this route; it also works with `roll_requests` off. No new flags or delegation operations.

GM review uses existing commands (no slash schema/registration change):

```text
/vc-story scene-view json:{"op":"entries"}
/vc-story scene json:{"op":"review-entry","key":"<entry key>","expected_revision":"<current fingerprint>","location_key":"<established exact named location>","adjudication":"<human ruling establishing legal access without unhandled costs or travel>"}
```

Establish genuinely new places through existing sourced world authoring and review first. Entry review rechecks the actual current owner/assignment/attendance, active owner-authored declaration, session, scene and unchanged prior location. It refuses stale/forged sources, different destinations and active encounters. It atomically updates saved location, writes a reviewed owner-arrival event and native scene presence, and closes the request; repeat review cannot apply again. Private entry stays character-private. Human review is deliberately not delegated to a model: ambiguous movement cannot become teleportation, an automatic access ruling or an inferred owner decision. This release does not automatically create the diner, Lena, opening hours, witnesses or a successful search. A pending entry does not bypass existing queued director work or native time/travel mechanics. Pending entries also appear in GM brief/intent context; all records participate in native backups.

Claims now distinguish `npc:<key>`, `character:<id>` and an empty narrator actor; established raw character IDs/NPC keys remain compatible. A PC describing their own saved position does not need an NPC witness; other actor observations still require actual native scene access. Movement still requires the saved position, and private native presence cannot be narrated publicly. Narrator/player disclosures require an actual audience-visible fact, not NPC knowledge; a PC speaker must also have access to it. NPC disclosures require that NPC's own matching known fact key/source reference, with unknown/retracted sources refused. Private-message audience checks use the actual recipient; repeating private text publicly still fails. NPC fact knowledge is not a substitute for witnessing movement. Unknown actors and unestablished disclosures remain rejected.

Bounded category/actor/entity/action/source/span diagnostics are retained in the private audit and fed into the existing correction retry; no additional provider retry is added. Mandatory narrative safeguards are not disabled or bypassed. Unrestricted model semantics remain unverified.

Required `scene-entry-test.mjs` exercises the exact diner wording, no-place/no-NPC creation, native review through the GM command and permission denial, ownership/stale/retracted sources, replay, private arrival, restart/snapshot restore, narrator/PC/NPC observation/disclosure boundaries, private-message/public leak refusal, actual diagnostic audit and GM retry. The production-only missing-location guard and its original regression test are included unchanged. All required offline suites must pass before release push/pull. Deployment does not mutate campaign data or restart the running bot.
