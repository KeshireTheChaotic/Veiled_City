# 10.1.0 — narrative authority and emergent continuity

Accepted typed intents are canonical adjudication inputs; human declarations own intent; native receipts own outcomes.

Opt-in creative GM narration now supports fresh places, ordinary NPCs, sensory scenes, nonbinding leads, rumors, conversation and protected-scene atmosphere. A sparse scene needs no prewritten environmental fact. Native travel/setup results receive destination fiction. Camera openings never place PCs or grant them witnessing. Native mechanics, canon, private information and PC/proxy choices remain protected. Unsupported material units are held without erasing independently valid siblings.

Meaningful accepted fiction persists as source-bound world memory. Audience recall requires acknowledged delivery, not a queued or uncertain send. Rumor/testimony remains subjective. Source revocation holds replay/recall without reversing legitimate committed mechanics. Cold emergent material can leave routine context and revive on entitled references; no source, character or receipt is deleted.

## Enable through authenticated Discord GM administration

The release does not automatically enable new flags. No local authenticated administrative connector exists in this execution environment. Once the owner has started the bot, a real GM can progressively use:

```text
/vc-city flags json:{"scene_continuity":true,"playable_narration":true,"narrative_authority":true}
/vc-city flags json:{"narrative_memory":true,"narrative_completeness":true}
/vc-city flags json:{"narrative_camera":true}
/vc-city flags json:{"narrative_encounters":true}
/vc-city flags json:{"narrative_salience":true}
```

For an initially unplaced/sparse campaign, enable camera with the master before requesting a scene. A genuine owner initial-position declaration can use native initial setup; existing placement, travel costs, locks or an active encounter cannot be bypassed. Otherwise use the existing owner-private setup control. Names/aliases are continuity identities, not a command grammar.

Rollback behavior with `/vc-city flags json:{"narrative_authority":false}`; dependencies cascade OFF. Disabling memory also disables salience. Disabling playable narration disables the new master. Existing accepted world events and delivered history remain intact.

## Scope and limitations

Native proofs certify source, actor, audience and effects, not every implication of arbitrary English. Newly generated ordinary GM prose has explicitly accepted residual semantic risk. Finite tripwires are defense-in-depth, not universal semantic detection. The isolated writer never receives all private character sheets/logs. Claims/safety labels do not manufacture authority.

Typed completeness measures projected coverage, not literary quality. Metrics are bounded process-lifetime counts/timings, not billed charges. Synthetic tests establish no live speed/cost/quality gain. One isolated writer is permitted per logical turn across NPC/scenery; direct ordinary observation uses one provider request, opted-in combined turns normally use the combined request plus one conditional writer. Fake tests use no provider network.

Default offline qualification now runs critical functionality/security gates. `npm run validate:extended` retains optional historical matrices; no assertions/tests were deleted. See the execution ledger for actual counts and deferred coverage. Salience scans are bounded and conservatively pin on overflow; very old nonroutine retrieval can require explicit historical inspection. New generic city-record/event kinds require no SQL migration (schema 460). Older code cannot render new queued prose safely; hold/reconcile it during code rollback, never replay effects or blindly resend messages.
