## Repair

- Scene requests use one current authenticated actor viewpoint, not an all-roster co-location requirement. Current public actor presence permits public scenery while unrelated/unplaced/private PCs continue independently. It does not establish anyone else's presence or knowledge. Actor presence must be active/actually-present/current-scene with active audience-compatible evidence. Scene facts and environment facts use the same native evidence/ancestry checks.
- Default scene recovery ignores native assembly/Director scopes that are not owner-authored scene requests. An explicit invalid scene proposal still fails its renderer; enabling flags cannot turn administrative assembly output into a fabricated player source or abort independent native orientation.
- Missing position produces specific truthful setup guidance, not generic neutral text or imagined arrival. Raw plans, character notes and old attempts remain nonauthorizing. Existing saved positions can be reconciled by the authenticated owner's existing check-in/arrival pathway; absent historical placement receipts are not reconstructed by guessing.
- Existing `/vc session present` offers an ephemeral owner-only select when initial position is absent, the session is in assembly, no prior native placement history or active encounter exists, and current native PC eligibility holds. Options include at most 12 existing nonhidden public, unrestricted, zero-cost/nonhazardous native locations, with explicit table-share or owner-private visibility, plus neutral refusal. No new slash schema/registration is required.
- Offers bind session/scene, current owner/control revision, exact immutable options and source, location/source revisions and a ten-minute lifetime. Human selection creates `owner_initial_scene_confirmation`, an explicitly initial/not-travel arrival, native presence and a terminal `scene_setup` receipt in one transaction. It changes only initial location/presence; it does not consume sources, resolve earlier actions, spend resources, roll dice or select other PC reactions. Forwarded, changed, revoked, stale and replayed choices cannot mint a new outcome. Existing private placement is not implicitly disclosed by repeat check-in.

## Expressive GM-owned scenery: owner-approved residual risk

The owner explicitly approved an audience-isolated scenery authoring stage under the same residual-risk policy as fresh NPC authoring. `gm_world_parts` version 6 / `scene_fresh_request` carries only bounded `fact_refs`, never prose, safety flags or claimed receipts. A current native source/owner/viewpoint envelope must exist before any writer request. The isolated packet contains only a safe public location name and eligible audience-visible native environmental evidence: no PC names/IDs/sheets, player text, GM notes, raw narration or arbitrary location summaries.

At most one conditional isolated writer is allowed per logical turn **across NPC and scenery**, including correction/restart paths. No unconditional second call was added. Ordinary turns without the request make no additional writer call. Missing/unsafe viewpoint never triggers it. Saved authored framing is reused, interrupted attempts remain held, and provider calls inherit the existing bounded retries/shared turn deadline. Normal provider request accounting remains in use; no synthetic token/cost savings are asserted.

Trusted authoring persists a source-bound `scene_fresh_authoring` record and immutable provenance event, explicitly `semantic_verification:false`. Native rendering labels/quotes the text as nonmechanical scene framing, not character outcomes or new durable changes. It revalidates source, audience, owner/control, viewpoint/presence/location and evidence on final publication, restart, private/public reuse and shared outbox delivery. All actual damage, movement, access, conditions, encounters, consent, Hope/Fear and other consequential outcomes still require their existing native receipts. Generated framing is excluded from general sourced-context evidence ranking; it is not a new objective fact or canon record.

This is **not universal semantic verification**. Isolation and provenance reduce leakage/authority risk but cannot prove every possible generated sentence harmless. Existing full-name/material tripwires, additional short registered-name/second-person tripwires and shape/control-character checks are defense in depth, not permission by absence of a match. They may conservatively hold innocent wording (for example an ambiguous first name). Unknown indirect references or implicit scene consequences remain a residual generative-prose risk approved by the owner; framing never confers native effect authority. No fixed sentence catalog or PVP30 exception was added. Named PC reactions/injury, forged requests and bad output remain held with GM-private diagnostics; safe native viewpoint output and independent work survive.

## Operator workflow after separately authorized deployment

Each owner runs `/vc session present`, chooses their own initial location and disclosure, or declines. Neither this implementation nor enabling flags confirms it for them. Once a viewpoint is established, ask naturally to describe surroundings. A split party need not be assembled into one room. A historical placement conflict, restricted/costly destination, active encounter, incapable PC or absent eligible location requires existing native review/GM world-authoring, not a setup override. Do not manually bulk-edit positions or replay old actions.
