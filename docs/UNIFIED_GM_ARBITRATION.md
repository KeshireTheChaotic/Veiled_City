## Current supported execution

The existing combined GM and Director calls share native scene boards and immutable decisions. Mundane PC no-roll/action requests reuse existing rules services. Standard NPC attacks reuse the actual encounter/template/Evasion/incoming defense, damage, Armor and death services through a distinct native AI capability. Exceptional independent NPC tasks require a real native objective/template; optional native stat-block Experience and extra spotlight expenses are additive before RNG. Player reaction invitations wait for authenticated owner submission. Source-bound native looking-to-GM or eligible actual action-roll results provide opportunity, not automatic attacks. No reaction/d20 generates Hope/Fear.

`stakes_kind` is a proposed effect class, never semantic proof. Attempt-only requests publish native attempt-only stakes, not the model's arbitrary justification or secret-bearing prose. Actual damage stakes require the incoming native attack adapter. Other feature effects remain unsupported until mapped. GM proposal text stays internal; owner notices render saved native facts only. Arbitrary GM prose does not become a player-facing mechanical receipt.

Owner controls use the existing `/vc-roll window json` endpoint: `{"op":"gm-reaction-review","request":"<native-decision>"}`, then `{"op":"gm-reaction-roll","request":"<native-decision>","revision":"<reviewed revision>"}` or `gm-reaction-withdraw` with the same fields. Review does not roll. Normal incoming `/vc-roll effect` review/defense/Armor remains authoritative; native AI attack dice may continue after exact owner defense confirmation. No registered Discord commands or production flags were changed.

`{"op":"gm-reaction-inbox"}` lists only the current owner's invitations and terminal/held statuses, including after restart. No foreign-character or GM scope selector is accepted.

Still **not implemented** by this bridge: generic adversary reaction-feature executor, multi-target feature mapping, arbitrary environment feature executor, special defense mapping, and NPC effects based on private result dependencies without separate disclosure/observable proof. These are explicit review paths, not evidence of end-to-end native feature support. Existing specialized native features and protected PvP remain available unchanged.
