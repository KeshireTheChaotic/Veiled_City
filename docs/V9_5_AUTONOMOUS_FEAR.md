# V9.5 autonomous PvP Fear

When an accepted PvP action roll produces Fear, Veilkeeper makes one bounded internal attempt to resolve the immediate consequence through native scene state. Narrative-duel paired rolls wait until the paired comparison is saved; each Fear then resolves independently in locked participant order. A damage-enabled PvP action resolves its action Fear immediately after its native attack receipt is saved. Reaction rolls are not action triggers.

If a current, audience-safe contextual effect exists, the native planner selects only an allowlisted move with its native adapter. Existing supported routes include a scene clock, an eligible established adversary's preparation in an accepted native encounter, and the source-grounded new NPC threat described below. The no-context NPC proposal is bounded by established venue/scene details and PvP objective/stakes. Native validators—not proposal fields—establish a collision-free identity, current location/presence, source, session, scene and audience. Its creation receipt explicitly grants no combat template, abilities, resources or knowledge. A separate native threat-progression event/receipt must immediately advance the established threat before the Fear effect can resolve. This is neither an encounter nor an attack and cannot change PC resources or compel a response. If no safe native consequence is supported, the trigger remains `needs_review`; no cosmetic or unrelated clock fallback is substituted.

Threat creation, separate progression, the final Fear effect and audience-bound publication reservation are idempotently linked. Private effects notify their actual entitled subject: normally the roller, but the defender for a native incoming attack. Bilateral-author-projection terms permit party-facing notice only for party-scoped effects. Fear accounting itself generates no Hope, campaign Fear, PC HP/Armor/Stress, forced response or additional PvP roll. A separately authorized NPC attack may change HP/Armor only through its distinct native attack, owner defense and Armor receipts.

The feature is enabled when `autonomous_pvp_fear` is absent or `true`. A GM/admin can preserve the manual Fear inbox workflow with:

```text
/vc-city flags json: {"autonomous_pvp_fear": false}
```

Re-enable with `{"autonomous_pvp_fear": true}`. The flag is campaign-scoped. Existing explicit `/vc-roll pvp fear-*` GM context/select/apply/reconcile commands remain available. Invalidated or unsupported obligations are marked `needs_review`; saved dice, pair results and unrelated actions remain intact. A startup pass retries only current `awaiting_move` triggers or a persisted autonomous decision, with a bounded batch of 12; it never rerolls or automatically retries reviewed records.

An existing clock is eligible only through a unique, active GM-established context binding the exact current scene, location and audience. Legacy clocks without this provenance are not guessed into scope. A unique current NPC attack context takes precedence over a clock, but must reference the exact fresh Fear source, damage-enabled profile, native encounter, template, reviewed applicability ruling and entitled defender. Automation does not prepare a fictitious human-GM offer or approve an encounter. It selects the already-legitimate request, waits for owner defense confirmation, then uses a separate verified internal capability for native NPC dice. A hit waits for the owner's Armor choice. The existing private `/vc-roll effect` incoming-defense and incoming-armor adapters wake the bounded coordinator; startup recovery can resume the same decision. `awaiting_owner` is not a completed Fear effect. A miss is a genuine terminal native attack outcome, not a fabricated injury.

Recovery follows native paired participant order or simultaneous target-window reservation order, not hashed record keys or dice arrival order. A later obligation reports `awaiting_prior_fear` without being spent or spuriously moved to review. Two Fear rolls remain two effect receipts. Existing NPC preparation can hold only unfinished, current owner-source-verified searches of that exact NPC; completed investigation receipts, independent sibling actions and other actors' unrelated actions remain untouched. The hold is a contextual revalidation requirement, not an invented failure or player response.

Route/access changes remain available through the existing authenticated native GM adapter. Hazards, revelations and feature costs without a supported native mapping remain `needs_review`, with a GM-private reason. Ambiguous routes, stale sources, changed native templates and unavailable authorizations likewise remain reviewable; no generic resource delta, cosmetic substitute or waived Fear is used. Direct entry also respects an explicit manual override, existing human selections and review holds; only authenticated reconciliation can reopen reviewed work. Post-effect retraction leaves native effects/resources saved while stale output is held. A stale source can require fresh native review for future dependent work; it is never restored by publication recovery.

No schema migration is needed. Rollback must retain establishment/progression, native dice/damage, Fear decisions/effects, holds and all acknowledged/uncertain outbox records. Disable automation first and hold unfamiliar records for reviewed recovery; never erase imported characters, reapply damage or blindly resend uncertain messages. Private threat identities cannot be silently reused for another owner's audience: an incompatible existing identity remains reviewable rather than being promoted or duplicated. Human assessment of contextual quality remains part of a separately authorized pilot.

Offline implementation tests use temporary SQLite fixtures, synthetic dice and network denial. They do not qualify model-authored narration quality, Discord live delivery, pilot suitability or paid-model usage.

The new-NPC adapter currently supports only its source-grounded native venue catalog. In-schema free text is not claim authority: proposed identity/profile/consequence prose outside that exact mapping stays private scope review. Published consequences render native structural facts, never `threat_label`, profile prose or an echoed negotiated objective. This prevents a proposal from laundering an unowned PC reaction into canon via a native creation receipt; it does not weaken the separate V95-01 source-verified NPC narration services.
