# R3 — durable native owner-roll notices

Implementation slice complete. All R0–R8 acceptance gates remain incomplete.

Added discord-roll-notices.js for one-attempt delivery of an already approved, source-qualified pending request. It refreshes the original authored Discord source through native intake, verifies current canonical owner/terms and exact live audience, claims a durable publication, sends a fixed stakes/odds notice with nonce and mentions disabled, retains returned transport identity and acknowledges only exact bot-message readback with unchanged source/audience. Nothing rolls, spends, moves a PC, grants consent or establishes a result. It is a native service, not an AI-callable publication tool, and is not yet root-composed.

roll-store.js now journals notice publication/response/uncertainty in the existing event table. No schema was added. One claim excludes concurrent sends. A lost acknowledgement remains uncertain and cannot be retried; a saved response can be read back and reconciled after cold reopen without sending again. The native delivery event and publication delivered status commit together and retain channel, payload, audience and term binding. Transport bookkeeping may retain a returned message ID after business authority changes; it does not acknowledge delivery or restore that authority.

ordinary-roll-preparation.js now provides a read-only request inspector binding every saved request field to its current accepted adjudication and native terms, including stakes/Difficulty, source, actor, IDs and revision. The notice sender uses that actual inspector rather than a boolean approval callback. Adjudication approval, feature activation/payment and the owner dice/Fear/outcome lifecycle remain separate required gates.

Initial notice checks exposed a real source-refresh defect: native intake compared JSON strings and treated reordered object keys as changed channel/message data. Replaced that comparison with semantic deep equality. A new regression proves equivalent property order preserves issued sources and actual audience change still revokes them. Six initial notice failures were traced to this defect; source/permission checks were retained. This fix is directly required for notice refresh, not a relaxed authority rule.
