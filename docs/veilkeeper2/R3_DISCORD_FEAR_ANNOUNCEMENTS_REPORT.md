# R3 — native Discord Fear announcement adapter (slice complete)

Added opt-in `discord-fear-announcements.js`. Native route evidence must match campaign, scene and owner. The adapter refreshes the complete owner-only audience, claims the held interruption through the coordinator, fetches the native channel and refreshes audience again before sending fixed mechanics text. The payload disables mentions and uses the saved attempt identity to derive a Discord nonce with uniqueness enforcement. No model text, secrets or NPC perceptions enter the message.

After sending, the adapter force-fetches the returned message and refreshes audience again. Exact bot authorship, guild/channel, body and audience must match before the coordinator acknowledges the bound attempt. Failure preserves uncertainty, or the existing delivering state if uncertainty bookkeeping itself loses authority. The adapter never makes a second send for an already claimed attempt. Successful acknowledgement retains the roll hold and reserved Fear; it does not spend or execute an attack.
