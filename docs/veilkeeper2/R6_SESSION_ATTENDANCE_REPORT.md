# R1/R3/R6 — native owner attendance and scoped source revisions (slice complete)

Added an opt-in native attendance adapter for `/vc-session` and `/vc session` present/arrive/absent/leave. It uses same-client observed commands, a trusted current-session/owned-character resolver, existing registered PC owner control, a scoped native character identity reader, active session/scene and fresh channel permissions. It changes attendance only. It creates no character, assignment, fictional arrival, location, movement, co-location, party membership, PC proxy, resource state or inferred PC action. Offscreen absence retains exclusive player control; unsupported proxy/background modes are held rather than granting PC autonomy. An already active check-in preserves its original present/late/guest marker and authority.

The read-only character identity adapter uses the existing native repository's `getCharacter`, verifies campaign and owner, and returns only identity/status fields. Export/import packet labels do not register actors or bootstrap mechanics. GM-private sheet fields do not enter attendance replies. Native session routing remains host-provided; ambiguous/unresolved selections require native review.

Attendance exposed a concrete multiplayer defect: the old global scene revision revoked another owner's issued source and pending action when someone else joined. Native scene snapshots now derive separate lifecycle and per-participant revisions, never accepted from callers. Source proof digests bind the owner's attendance generation and scene lifecycle while ignoring unrelated participant updates. Equal initial epochs preserve the former digest format; pre-metadata snapshots bootstrap from their current native revision on the next write. Own absence/rejoin and scene close/reopen cannot resurrect issued proofs. Legacy reader adapters without native epoch metadata remain conservatively bound to their global scene revision. Channel, message, session and actor-control checks remain exact.

The exclusive interaction root optionally composes attendance before other native command callbacks. Durable interaction claims prevent repeat scene writes/replies across restart. Private acknowledgements and confirmation uncertainty use existing native transport receipts. The scene write updates only closed scene fields; it does not rewrite actor control revision, character data or canonical PC pools. Initial authorization errors are caught privately by the root; standalone callers must handle them privately.
