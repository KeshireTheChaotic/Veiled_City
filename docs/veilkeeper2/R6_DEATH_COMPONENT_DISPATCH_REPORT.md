# R3/R6 — native death component dispatch (slice complete)

Added an opt-in Discord `interactionCreate` listener for known server-issued death controls. It privately defers with the installed SDK's `MessageFlags.Ephemeral`, then invokes the existing observed-decision, source-authority and fixed native ingress chain. It never parses player prose, invokes inference, selects a move, rolls fate or installs production routing. Other commands/buttons and unknown tokens pass through untouched. Private confirmation text is fixed and never includes raw exceptions, actor state or model text.

The dedicated native interaction receipt store claims the exact interaction/user/message/channel/prompt/token binding before acknowledgement. Duplicate events, including after reopening the receipt file, cannot process or reply again. Acknowledgement, native committed outcome reference/hash, and private reply delivery have separate states. Defer ambiguity prevents processing. Native failures are held. A confirmation failure retains a committed effect and marks the reply uncertain. A crash or storage failure after a canonical effect but before saving the interaction outcome remains a native reconciliation hold; this code does not automatically replay either effects or replies. Closing the listener aborts pending audience/source work before further effects.
