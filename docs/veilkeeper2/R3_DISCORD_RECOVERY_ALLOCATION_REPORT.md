# R3 — explicit native recovery allocation controls (slice complete)

The owner-only death component chain now offers explicit recovery splits after a saved Risk It All Hope outcome. Native terms derive the budget from the saved Hope die, cap it at marked HP plus Stress, and enumerate every legal split. At most thirteen buttons are needed, arranged in rows of five. Labels state exactly which marked slots will clear. Nothing is preselected, inferred from chat/silence, or forced toward clearing HP.

The native ingress binds the initial outcome hash, exact canonical after-state and complete actor frame to the delivered prompt and observed owner click. It maps the opaque server-issued option to a fixed HP/Stress pair and calls `allocateIncomingDeathRecovery`; it never submits a generic patch or draws dice. Native evidence is rechecked before effects; the fixed allocator checks exact budget, ordered ownership/source ancestry and full compare-and-set, then saves one immutable recovery receipt. Transaction-boundary checks retain the current authenticated owner source; they do not compare pre-recovery terms against the operation's own post-state. After commit the old prompt is stale. Receipt replay uses the existing native allocation API and preserves dice rather than reconstructing a new click.
