# R4 — conversational GM behavior

Implementation and evaluation in progress. R4 and the full R0–R8 rebuild are not qualified.

The previous runtime produced unsupported PC blocking, feelings, duplicate character portrayals, long monologues and administrative refusals in actual local-model samples. Improving those behaviors is the purpose of this change; fluent output alone is not acceptance.

## Implemented changes

- Provider-neutral GM guidance prioritizes the current conversational moment, distinct NPC speech, fair consideration of unusual approaches, proportionate detail, comfortable pauses, direct OOC clarification and genuine player response windows. It retains source, knowledge, rules and player-ownership limits.
- Both providers distinguish audience-scoped scene notes from the exact current player message. Both remain user-role data; neither is promoted to system instructions or fabricated assistant history. GM-private planning keeps its original serialization and separate authority path.
- Local generation explicitly sets temperature 0.7, top-p 0.8, top-k 20, presence penalty 0 and repeat penalty 1. The installed model previously inherited temperature 1 and presence penalty 1.5. This is a continuity-oriented configuration choice, not proof that sampling caused every failure. Thinking is an explicit native-only provider option; its reasoning is not returned as prose. No automatic retry, remote fallback or extra AI capability was added.
- Targeted material review now catches the observed PC/proxy movements, gestures and explicit emotions. Independent NPC allegations are allowed with leading or trailing speech attribution. Actor names containing regex punctuation are matched literally. Harmless independent paragraphs remain available for review. Screening is still incomplete and never grants publication authority.
- An opt-in synthetic conversation evaluation runs the actual native source/context/gateway/review path with real local Ollama. It saves every response, source hashes, metrics, privacy observations and case rubrics in a new non-overwritable directory. One call per case; no Discord, gameplay writes, cloud inference or automatic semantic pass. Eight development cases and eight separate holdout cases are supplied.

## Validation and qualification boundaries

Recorded runs and final native test results are in R4_CONVERSATION_MODEL_EVIDENCE.json and R4_CONVERSATION_HASHES.json. R4_CONVERSATION_AFFECTED_TESTS.json lists the fresh native import-dependent selection, including literal dynamic imports. Earlier completed unchanged suites are not release qualification.

The first five eight-case model runs used the installed qwen3.5:4b: original baseline; expanded guidance; explicit sampling; shorter guidance/message framing; and thinking with the shorter guidance/framing. All returned drafts and excluded the synthetic GM-private body, but each had material quality failures. Guidance-only and sampling-only were insufficient; shorter framing improved some ownership behavior while leaving speaker confusion, unsupported clues and backstage language. Thinking did not establish reliable quality. All failures are retained. Native unit fixtures and a model's confident testimony are never evidence that alleged promises, witnesses or outcomes are objectively true.

The owner subsequently authorized downloading/evaluating larger local models. qwen3.5:9b was downloaded successfully and tested in non-thinking development/holdout runs, a thinking development run and a revised-addressing development run. Some dialogue is more coherent, but duplicated PC viewpoints, answering for the wrong addressee, invented clue fragments, an unsupported footage-deletion deadline and a pursuer invented from ordinary footsteps remain failures. A question addressed to a human-controlled role must not simply be answered by an independent NPC. Confident NPC allegations remain allowed as speech, not established history. The 27B download completed and its non-thinking development run also failed: unsupported PC leaning/letter fragments, wrong-addressee response and a backstage refusal. First response took46983ms and later responses14254-29071ms. Its thinking-mode diagnostic is now running. No default model switch or quality acceptance is justified yet.

Final native validation for the current source: **185/185 checks passed across 29 files**, Node v26.13.0, 29083.5922 ms, concurrency 4; .reports/r4-conversation-addressing-tests-20261111.txt. A previous dependency run had one wording-sensitive test failure ('prove' versus 'proves'); the assertion was corrected and the actual actor/statement lineage checks passed. Subsequent complete affected runs followed actual formatter changes; no unchanged passing suite needs another run.
