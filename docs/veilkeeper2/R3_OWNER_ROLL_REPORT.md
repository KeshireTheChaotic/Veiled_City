# R3 — native owner roll evidence

Added a native read-only inspector for ordinary unmodified PC Duality rolls. It loads request, actor, delivered stakes and saved roll by native references. Current owner/control revision, scene, request status, Difficulty/stakes equality, audience coverage and native event ordering are checked. Dice must originate from authenticated owner evidence after the notice. Pure arithmetic uses saved faces, draws no new dice, and commits no effects.

Fresh command from bot: `node --test tests/veilkeeper2/r3-owner-roll.test.mjs`. Actual outcome: 3/3 passed, zero failures/skips, 54.7124 ms. Cases cover threshold/critical arithmetic, stale/proxy control, changed stakes, wrong owner/origin, pre-notice ordering, unsupported modifiers and invalid faces. Native evidence readers are synthetic; no live owner roll or Discord notice was used. Existing passed suites were not rerun.

This inspector is not a registered AI tool or executable roll operation. Modified/help/tag/team/PvP rolls are deliberately unqualified in this slice and remain mandatory final parity work. Native request construction, delivery/roll persistence, immutable proof revision checks, once-only effect consumption, resource outcomes and full catalog parity remain open. No successful game effect is authorized by the returned arithmetic. R0–R2 holds and R3–R8 gates remain incomplete. No production change, migration, deployment or phase push occurred.
