## Source and authority

The existing combined GM request uses existing `player_intents` with `type:other`, `resolution:conversational`, and two explicit operations: `personal_commitment_candidate` and `proposal_campaign_canon`. No new provider, router, card/effect adapter, consent delegation, schema migration or mandatory response field. Native `persistPlayerIntents` performs proposal/acceptance as before. The shared read-only `ownerSemanticSource` then verifies actual native accepted rows, immutable raw source/hash/UTF-16 range, owner/control revision, current scene/session, exact audience, unconsumed/non-withdrawn span and current world-input ancestry. It never accepts a serialized model receipt. Structural source/quote/OOC tripwires may reject an optional proposal; they are not a new verb whitelist or universal semantic detector.

### SEM04 — optional personal candidate

- `index` no longer extracts vows or wishes before the GM. Six-argument legacy `captureArcCandidate` cannot infer new records; native callers must supply a real current accepted intent reference. Normal transactional state commit creates version-2 private `arc_candidate` records; generation preview rolls them back.
- Source wording must be an exact first-person declarative span, not a nested quote/attributed substring. Typed quoted/conditional/hypothetical/reported proposals never become accepted immediate candidates. No `vow`, `promise`, `wish` keyword creates authority or chooses an arc type: new optional candidates use nonbinding `desire` until authenticated owner confirmation.
- Confirmation retains revision/expiry/current owner checks, revalidates source/principal/scene and exact candidate text/type against the original proof. Changed or retracted proof cannot establish an arc. Native candidate arbitration cannot present modified terms as an authenticated quote. Independent valid actions remain available when an optional candidate is held for review.
- The original current owner can reject/defer a v2 nonbinding candidate after source retraction, a scene change or expiry. This terminal cleanup still requires the current owner, pending record and exact revision; it cannot establish fiction. Legacy candidate checks remain unchanged.
- Existing owner-stated arcs, their types and history are unchanged. Existing legacy pending candidates remain inspectable/confirmable by their original current owner through the native workflow; no automated reinterpretation or backfill occurs. Explicit native owner `state` remains available.

### SEM05 — explicit private canon proposal

- The exported canon-keyword detector and its GM retry branch are retired. Only a current immediate typed `proposal_campaign_canon` request can require a bounded missing-payload correction. Mention, discussion or quotation alone never forces that workflow.
- `applyCanonProposalDrafts` rereads native accepted intent/source; exact proposed value must occur in the owner-authored request, not merely in model prose. Model-only payloads, foreign owners, public scope, another message and mismatched values are blocked; rejected private canon events cannot bypass that gate through conversion.
- New rows use `source:typed_private_proposal_v2`; GM-private `canon_proposal_source` binds exact terms, actual native request and audience. They remain pending, not canon. Native human-GM promotion and direct linked-conflict resolution both revalidate the proof. Missing v2 proof, stale owner/source/scene or widened visibility fails closed. Explicit rejection can clear a stale proposal; legitimate already accepted canon is not reversed on retraction.
- Historical/imported canon proposals retain their native human-review/read workflow. They are not automatically upgraded, reclassified as owner consent, or rewritten. New versioned origins cannot acquire that legacy missing-proof allowance.

### SEM07 — dossier traits

New GM dossier entries may provide closed `decision_profile` attributes. Numeric risk/violence/honesty/loyalty/patience/ambition/compassion/lawfulness/collateral/contract/reciprocity fields are integers 0–100. `veil_awareness` is `limited` or `aware`; `supernatural_ethics` is bounded descriptive text. Unsupported keys, scores or shapes reject atomically. Missing values use conservative defaults (50, collateral 75, awareness limited, ethics unspecified).

Court, ghost, veil, green, oath and similar descriptive words no longer grant scores, awareness or rule-like knowledge. Explicit knowledge/unknown boundaries retain their existing actor-owned sources; portrayal is not a new capability. Existing authored/historical profiles are skipped instead of automatically rewritten, including a first bootstrap over a preexisting campaign. Reference/relationship and private-memory scope gates remain native. Packaged prose was not edited to recreate old lexical results; owners may author explicit dossier attributes for future seeds. This phase does not retroactively reset existing profiles.

## Limits and rollback

Semantic classification remains fallible: exact provenance does not prove every nuance of arbitrary language. Native framing/structural guards plus private, optional candidates prevent interpretations from becoming commitment/consent or facts. A misclassified candidate can be rejected by its owner; canon needs native human review. Unknown first-person/ambiguous forms may stay unproposed, and quoted/conditional semantics are not claimed universally solved. No new keyword detector or automatic approval is introduced to improve finite fixtures.

Additive v2 candidate/proof records only; no SQL migration, imported-character overwrite or historical outcome rewrite. Rollback keeps these records as inert history and never replays effects or deletes campaign data. Reverting to legacy code reopens known lexical candidate/retry/trait defects and loses new-source revalidation; it is not a safe deployment recommendation. Preserve 05R output guards. Deployment and any live/paid quality pilot remain separately unauthorized.
